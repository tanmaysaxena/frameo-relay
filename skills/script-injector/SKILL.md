# Script injector

> **Host note.** `$RELAY_HOME` below is the folder that holds `scripts/relay_check.py` and `skills/`. In Claude Code and Cowork it is `${CLAUDE_PLUGIN_ROOT}`. In any other agent (Codex, Gemini CLI, Cursor, ...) it is `$FRAMEORELAY_HOME` if set, else `~/.frameorelay` (made by `scripts/install.py`), else the folder of the clone or plugin copy this skill came from. Resolve it once and reuse it. Tool names here are the Frameo MCP's own (`generate_videos`, ...); your host may prefix them (for example `mcp__frameo__generate_videos`). Subagent steps: if your host cannot spawn subagents, do them yourself in sequence. Details: `$RELAY_HOME/docs/hosts.md`.

Turns a shared script into the plan the relay runs on, and starts the run. It is the front door of the `frameorelay` plugin. Hard rules, in order of importance:

1. **Draft, then approval, then write.** Everything below happens in a scratch folder until the owner gives a real yes to the shown plan. Only then does `frameo-jobs/<job-id>/` get written and the conductor start.
2. **You never call a paid Frameo tool.** No `generate_*`, no `analyze_media`, no `run_ffmpeg`. Free reads only (`whoami`, `list_models`, `list_skills`, `get_skill`, `list_presets`, `get_presets`, `list_projects`, `list_characters`, `search_voices`). "Trigger the agents" means starting `frameorelay:conductor`, which spends only inside the approved total.
3. **Invented words are always visible.** Any dialogue you write is marked `source: "generated"`, listed on its own in the plan, and not spoken or voiced until approved.
4. **The sensuality ceiling is set in words, never tested against the filter.** For any romantic or heated scene, record the script's ceiling (or ask: clothed / implied / silhouette), put it in `style.avoid`, and write one softer fallback prompt per heated segment. See `$RELAY_HOME/skills/conductor/references/content-boundaries.md`.

## Ask first (one `show_choices` card where Frameo cards exist, otherwise a short list)

Skip anything the user already said, a saved `/brief` note already settled, or the user's personal defaults file already covers (`references/user-defaults.md`: look, voices, music, dialogue display, transitions, setting; apply them, state them once in the plan, and ask only what they do not cover, such as the voice for an extra character). Apply `references/prompt-quality-rules.md` to every story.

- The script (pasted, a file path, or attached; a PDF with no reader: `pdftotext -layout`). Story or marketing?
- Shape and length: aspect ratio, a **target and a maximum** in seconds, and the resolution tiers (default: 720p clips finished by upscale to 1080p, about 28 credits per second for clips and about 0.9 for the upscale; offer a separate 480p draft pass only if the user wants to judge the story before paying for 720p: it costs about 46% of a 720p pass and does not carry over, so every clip is regenerated afterwards; say the cost of each).
- **Style direction** (see Step 3), including whether characters and world have **different looks**.
- **Dialogue mode**: `as_written`, `fill_gaps` (default) or `full_creative`; and **delivery**: spoken in voices, speech bubbles only, or both. If voiced, one voice per character and a narrator voice that differs from every character unless the owner says otherwise. If shown as text: bubbles for dialogue, caption boxes for narration, or neither.
- Sound: background music and sound effects wanted? (Default for a story: yes, a bed per mood and a few foley cues; ask for the mood in words.)
- Shot stills: a first AND a last frame per shot (default for continuity) or first only.
- **Content boundary**: if the script has explicit sexual content, say up front that the plan is sensual and non-explicit (clothed, implied, cut away) and show what that means; never plan or prompt explicit imagery.
- Language of spoken lines.
- Which workspace: read `whoami`; if two workspaces exist, ask and pin one for the whole job. Check the balance there, and that the chosen voices exist in that workspace (`search_voices` with the exact name).

## Steps

0. Run `whoami`. If Frameo is not connected, stop and say so plainly. Note the workspace id. Then `list_models(kind="video")` and `list_models(kind="image")` and copy the fields the validator needs into `job.limits.models` (see `$RELAY_HOME/skills/conductor/references/relay-schema.md`).
0b. **Is it already a panel script?** If the script has no per-shot breakdown (an id, length, camera, visual, dialogue, narration, sound for every shot), stop and run `frameorelay:panel-writer` first: it turns the story into a validated panel script the owner approves, and writes `<name>.panels.json`. Use that as the script from here. A script that already has the table passes `python "$RELAY_HOME/skills/panel-writer/scripts/panel_check.py" check <file>` and needs no rewrite. Mapping: shot = scene, `Join` = chain (`hard cut` starts a chain of one), `Length` = segment seconds, `Setup` and `Cast on screen` = locks, `Camera` + `Visual prompt` = the sealed prompt, `Dialogue bubbles` = dialogue lines (`[generated]` = `source: "generated"`), `Narration (VO)` = the narrator's lines, `SFX` and `BGM` = the sound plan. Do not re-split a panel script; the owner already approved its shots.
1. **Read the script once.** Split it into scenes, one per continuous action or speech. Read `references/scene-splitting.md` for the rules. Group scenes into **chains**: scenes the script marks as the same take, or that carry straight on, form one chain; everything else is a chain of one. A chain is cut into **segments** of at most 30 seconds; a chain that fits in 30 s is ONE clip, rendered as "one continuous shot".
2. **Cast, places, props, voices** become `locks.items` (descriptions only; the conductor makes the images with Frameo's `character-sheet` / `story-assets` skills). Give every speaking character a `voice_id` slot; if none is chosen yet, mark it as pending and list candidates from `search_voices`. A narrator who is never on screen is a character lock with `voice_only: true` (voice, no image).
3. **Style direction.** Ask for it as free text, reference images/clips, or a pick from Frameo's looks (`list_presets`, `get_presets`). If the owner gives nothing, propose 2 to 3 options in visible terms and say the conductor will make cheap test stills to choose from. Write the `style` block: `look`, `palette`, `lighting`, `lens_and_camera_language`, `pacing`, `avoid`, and an **`anchor`** (at most 60 words, plain visible description, no brand or director names). The anchor is pasted verbatim into every keyframe and clip prompt. If the owner names franchises, games or films as the look ("like <title>"), translate each into visible terms (line, shading, palette, texture, motion) for the anchor and every prompt; the names themselves never go into a prompt. For a split ("characters like X, the world like Y") write two sentences in the anchor, one per half, and keep them in every prompt.
4. **Dialogue.** Keep every line the script has (`source: "script"`). Where a scene shows a speaking character with no line, and mode allows it, draft one: read `get_skill(skill_id="video-script")` for the format (spoken lines sized to the clip, on-screen text kept separate) and `get_skill(skill_id="video-prompting", path="video-guide-seedance-dialogue.md")` for timing. Frameo has no text-writing tool, so you write it, using Frameo's method. Mark `source: "generated"`, `approved: false`, and keep the words under about 2.5 per second of the segment. Lines must fit the cast and the style.
5. **Segment drafts.** Prefer single-beat clips of 6 to 10 s over 30 s montages: long multi-beat clips morph at their beat changes (see conductor gotchas). For each segment write: duration (whole seconds), a first-frame description, a last-frame description (the loose `end_target`; with the first frame it is a still the conductor makes per shot) (a loose steering image only), `join_motion` (cut joins at low-motion moments), and the **sealed prompt**: read `get_skill(skill_id="video-prompting", path="video-guide-seedance.md")` first. Open the prompt with the style anchor verbatim. Never write "previous", "as before", or a shot number: the model never saw the other clips. Name where people and camera end up.
6. **Write the scratch draft**: `<scratch>/relay.json` (shape in `references/plan-template.md` and the conductor's `relay-schema.md`) and `<scratch>/plan.md`. Run
   `python "$RELAY_HOME/scripts/relay_check.py" validate <scratch>/relay.json --scratch`
   and fix every FAIL before showing anything. If `python` is not found, try `python3` or `py`.
7. **Show the plan** (`show_plan` where cards exist, otherwise `plan.md` in chat): the chains and segments with seconds, the cast and voices, the style anchor, **a separate "Generated dialogue" section** (every invented line, who says it, where), the on-screen text plan (bubbles, captions), the voices table and the sound plan, what is NOT being generated, and an honest cost estimate. Do not guess prices: you cannot quote paid work with the free tools alone, so give the model's `credits_per_second` from `list_models` times total seconds as a rough floor for 720p (add about 800 credits for references, keyframes, speech, music and analysis, and about 0.9 per second for the 1080p upscale), then give the budget range measured on real runs, from `$RELAY_HOME/docs/credit-economics.md` (about 8,600 to 14,700 credits for 4:30 of film, from no retakes to heavy retake rounds) and say the conductor will quote exactly (`estimate_cost`) and ask for the single up-front approval including references, keyframes, a retake allowance (propose 30%, set `approval.retake_allowance_pct`; 15% is the validator default and is tight if the user will ask for motion or fix passes) and analysis before anything is generated.
8. **Wait for a real yes.** A change request means edit the scratch draft and show it again. Never treat silence or "sounds good" about the idea as approval of the plan shown.
9. **On yes:** create `frameo-jobs/<job-id>/` (in the working folder, or where the owner said) and copy `relay.json` and `plan.md` into it. Then invoke `frameorelay:conductor` with the job folder. If the owner asked to stop early (for example after keyframes), pass that as `through`.

## Series chapters (a chapter planned by book-breakdown)
If a `series` block or a book brief is present, do not re-ask the style, cast or voices: take them from `book/bible.json`. Put `shared_from: "bible:<id>"` (and `variant_of` for an outfit or state variant) on every lock the bible covers, set `job.frameo.module_id` to the chapter's own module, write the chapter's content ceiling into `style.avoid`, and set `approval.approved_total_credits` to the chapter's cap only after the user approves. The user sees all chapters together in the book plan, not one by one. See `$RELAY_HOME/skills/book-breakdown/SKILL.md`.

## Done

The owner has a validated, approved plan in `frameo-jobs/<job-id>/`, every invented line was shown and flagged, no credit was spent by this skill, and the conductor has been started (or the owner chose to stop at the plan).
